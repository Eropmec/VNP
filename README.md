# Конструктор визуальных новелл — этапы 0–1

Фундамент: формат проекта (схемы, модели, валидатор), рантайм на Godot, который этот
формат проигрывает, и живое превью, связывающее их. Тестовый проект — «Старый дом».

```
schema/                 JSON Schema — единственный источник правды о формате
editor/vnformat/        Python-пакет формата
  models/               pydantic-модели, СГЕНЕРИРОВАНЫ из schema/ — руками не править
  project.py            загрузка / сохранение проекта
  validate.py           проверка проекта, сообщения по-русски
  expr.py               функции ядра, типы выражений, запись формулой
  io.py                 JSON и таблицы локализации
runtime/                рантайм Godot 4.4+ — см. runtime/README.md
tools/codegen/          генерация моделей из схем
editor/app/              редактор: граф сюжета, свойства, проблемы, плейтест
editor/run.py           запуск редактора
tools/live_preview.py   живое превью: игра в окне + перезагрузка при сохранении файлов
tools/build_game.py     собрать игру без редактора (Windows / Linux / Android)
tools/pack_game.py      проверить проект и упаковать в runtime/game (для ручного экспорта в Godot)
tools/runtime_check.py  проверка протокола редактор ↔ рантайм и задержек
tools/make_demo_assets.py  ассеты-заглушки для демо
samples/demo/           «Старый дом»: глава, 3 сцены, ветвление, 3 концовки, 2 языка
tests/                  113 тестов; тесты рантайма и сборки — с Godot (VN_GODOT)
```

## Редактор (этап 1)

```
py editor\run.py                 # откроет последний проект или демо
py editor\run.py путь\к\проекту
```

персонаж, эмоция с картинкой, текст, фон с превью, позиция, переход, музыка, звук, варианты выбора.

## Сборка игры

**«Игра → Собрать игру…» (Ctrl+B).** Выбери, для чего — Windows, Linux или Android (APK), —
и режим: «Для игроков» или «Для проверки» (с консолью ошибок). Нажми «Собрать».

1. Проект сохраняется и проверяется; с ошибками сборка не начнётся — кнопка «Показать проблемы».
2. Если нет шаблонов экспорта Godot, они скачаются сами — только нужные файлы (~30–100 МБ),
   а не весь архив на 1,2 ГБ.
3. Готовая игра — один файл в `<проект>/build/<windows|linux|android>/`, кнопка «Открыть папку».
   В exe уже есть всё: проект, картинки, звук. Название окна, версия и разрешение — из «Настроек игры».

**Android — один раз:** поставь [Android Studio](https://developer.android.com/studio) и открой её
(она докачает SDK). Окно сборки найдёт SDK и Java само; если нет — укажи папки в нём
(обычно `%LOCALAPPDATA%\Android\Sdk` и `C:\Program Files\Android\Android Studio\jbr`).
APK подписан отладочным ключом Godot: его можно ставить на свои телефоны (разрешить установку
из неизвестных источников); для Google Play понадобится свой ключ — появится позже.

Без редактора: `py tools\build_game.py [проект] --godot C:\Godot\Godot_v4.7.2-stable_win64.exe --target windows`.

Ошибки проверки видны сразу: красный значок на узле, список в панели «Проблемы»
(двойной клик — перейти к узлу), подробности в «Свойствах».

## Как устроен проект на диске

```
project.json                 метаданные, стартовый узел, языки
story/graph.json             узлы и рёбра — только логика
story/layout.json            координаты узлов — только вид (не конфликтует в git)
story/scenes/sc_*.json       содержимое сцен: список команд
db/variables.json            переменные
db/characters/ch_*.json      персонажи: имя, цвет, эмоции → спрайты
assets/registry.json         реестр ассетов: ID → файл
locale/<язык>.csv            тексты: id,text
```

Ключевые правила формата:

- **Всё ссылается по ID с префиксом:** `n_` узел, `e_` ребро, `sc_` сцена, `c_` команда, `o_` вариант выбора, `v_` переменная, `ch_` персонаж, `a_` ассет, `str_` строка.
- **Тексты не лежат в сценах:** сцена хранит ключ `str_…`, текст — в `locale/<язык>.csv`. Перевод добавляется без правки сцен.
- **Выходы сцены — порты.** Каждый вариант выбора и `jump` создают порт `p_…`. Если сцена может дойти до конца без выбора, у неё появляется порт `next`. Рёбра графа идут из порта в узел. У ветвления порт `else` — «иначе».
- **Ребро в главу ведёт в её первый узел** (`entry`). Из главы целиком рёбер нет — только из узлов внутри неё.
- **Условия и эффекты — дерево:**

  ```json
  { "op": "and", "args": [
      { "op": ">", "l": { "var": "v_sanity" }, "r": 3 },
      { "op": "call", "fn": "visited", "args": ["n_cellar"] } ] }
  ```

  Формулой это `рассудок > 3 и visited(n_cellar)` — `vnformat.expr.to_text()`.

## Что проверяет валидатор

| Уровень | Проверки |
| --- | --- |
| Структура | Каждый файл по своей схеме. Узел и команда проверяются по схеме своего типа, поэтому ошибка звучит как «не хватает обязательного поля «text»», а не «не подходит ни под один вариант» |
| Ссылки | Переменные, персонажи, эмоции, ассеты (и их вид: картинка/звук), сцены, узлы в `visited()`, ключи текстов |
| Граф | Выход без ребра; ребро из несуществующего выхода; два ребра из одного выхода; рёбра из глав и концовок; первый узел главы; циклы вложенности |
| Сюжет | Узлы, недостижимые от старта; узлы, из которых нельзя дойти до концовки (тупики и замкнутые циклы) |
| Типы | Условие должно давать да/нет; нельзя сравнить логическое с числом; в целую переменную нельзя прибавить дробное; арность функций |
| Переменные | Значение по умолчанию подходит по типу и диапазону; уникальные ID и имена |
| Локализация | Нет текста на основном языке — ошибка, нет перевода на дополнительный — подсказка; дубликаты; неиспользуемые строки |
| Файлы | Файлы ассетов существуют; имя файла сцены/персонажа совпадает с ID; битый JSON — с номером строки |

Пример вывода на проекте с ошибками:

```
[ОШИБКА] story/graph.json: ребро e_intro_down — у узла n_intro «Прихожая» нет выхода p_dwn; есть: p_down, p_leave
[ОШИБКА] story/graph.json: узел n_intro «Прихожая» — выход p_down никуда не ведёт (выход создаёт: сцена sc_intro → команда c_choice → вариант o_down)
[ОШИБКА] story/scenes/sc_intro.json: сцена sc_intro → команда c_show — у персонажа ch_anna нет эмоции «happy»; есть: neutral, sad, scared
[ОШИБКА] story/scenes/sc_intro.json: сцена sc_intro → команда c_s1 — не хватает обязательного поля «text»
[ОШИБКА] story/scenes/sc_intro.json: сцена sc_intro → команда c_choice → вариант o_down — нельзя сравнить логическое и целое оператором >
[ВНИМАНИЕ] story/graph.json: узел n_cellar «Подвал» — до узла нельзя дойти от начала игры
```

У каждой проблемы есть `code` (для тестов и фильтров) и `path` — путь к полю, например `commands[6].options[0].condition.l`. По нему редактор откроет нужное место. `--json` выводит всё это машиночитаемо.

## Решения, отличающиеся от черновика спецификации

- **Ссылка на переменную** — `{"var": "v_sanity"}`, а не строка `"$sanity"`: иначе строку-константу нельзя отличить от переменной.
- **GDScript-классы из схем не генерируются.** Godot читает JSON как словари; проверку делает редактор при сохранении и сборке, а рантайм сверяет только `format_version`. Один валидатор вместо двух.
- **Числа при сохранении нормализуются:** `3.0` пишется как `3`, чтобы сохранение не меняло файлы ради «.0» и не шумело в git.
